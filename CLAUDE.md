# HRIS frontend

React + Vite + Tailwind v4. All styling is Tailwind utilities plus `src/index.css`; there is no other styling system.

## Ground rules for design work

Restyling is visual only:

- Allowed: `src/index.css`, Tailwind classes, `className`/`style` attributes, decorative elements with no text (glows, icons beside existing labels).
- Never change: any visible text (labels, headings, placeholders, messages, table headers, empty states), data, API calls, mock data, form field names/validation, state, handlers, routing, props, conditionals, loops, calculations, or i18n. Don't remove, reorder or hide elements, and don't rename files, components, variables or CSS classes other code depends on.
- If a design change would break a rule, skip it and ask.
- No hard-coded hex values in components; every color, radius, shadow and blur is a token in `src/index.css`.

## Design system: Slate & Sky — Glass + Gradient

### Where things live
- **Tokens:** top of `src/index.css`. Light values on `:root`, dark values repeated under `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` and `:root[data-theme="dark"]`. Keep the two dark blocks identical.
- **Tailwind names map onto the tokens** in `@theme`: `bg-bg`→`--bg`, `bg-surface`→`--card`, `bg-surface-2`→`--tint`, `border-border`→`--line-strong`, `text-ink`→`--text`, `text-ink-2`/`text-ink-3`→`--text-muted`, `brand`→`--accent`, `brand-dark`→`--surface-strong`, `good`/`warning`/`critical` (+ `-tint`)→status text/bg. Prefer these utilities in components.
- **Theme:** `data-theme="light"|"dark"` on `<html>` (`src/lib/theme.ts`), defaulting to the system preference and saved in localStorage; toggle is `ThemeToggle` in the top bar.
- **Font:** Lexend (300–700), fallback `'Segoe UI', system-ui, sans-serif`.

### Component rules
- **Background:** `.app-background` is a plain `--bg` layer fixed behind everything (no glows, no frosted panel around the main area).
- **Floating surfaces** (modals, drawers, dropdowns, toasts): use `.glass-surface` + a radius utility (modals `rounded-[var(--radius-modal)]`, dropdowns `rounded-[var(--radius-dropdown)]`). Despite the name they are solid `--surface-raised` (light #F7F9FC, dark #152036), not translucent: a modal sits on a blurred backdrop, and a nested `backdrop-filter` can't blur the page, so translucency would show the page through. The fill lives on `::before`, so fixed-position children still position against the viewport.
- **Modal backdrops:** `.overlay-backdrop`.
- **Sidebar:** `.sidebar-item` (36px, 13px/500, `--nav-text`, 20px icons); hover only when inactive; active = a raised card (`--nav-active-bg`: white / #1B2842 in dark, `--nav-active-text`, `--nav-active-shadow`) with the icon in a 32px `--grad-primary` tile (radius 7, `--shadow-logo`, 20px icon in `--nav-active-icon`); no arrow. Chosen so the selected page never looks like a solid-gradient button. Section labels 10–11px/600 uppercase, letter-spacing .1em, `--nav-label`. Exception: in the full sidebar (`FullNav`), group headings are 12px/600 in normal case, start at the same 12px inset as the page rows, and put the fold arrow on the right; single-module sections (Time & Attendance, Leave, Insights…) render as an icon row with a › arrow rather than a heading, so a folded section still shows what it is.
- **Roles and permissions** (`src/lib/permissions.ts`, the ONLY place access is decided): six fixed roles (system_admin, super_admin, hr, approver, accounting, employee), one per account. System Admin is our team, for maintenance only ("System workspace"): the client's plan and seats (Administration › Clients & Subscriptions, see Subscription & seat limits below), support tickets (`lib/support/store.ts`, `/admin/administration/support`: Super Admin, HR and Accounting file and follow their tickets, System Admin answers and sets status/priority), and user accounts with any role; no HR, pay or attendance data. `PERMISSIONS` is the approved access matrix (feature × role → `full` / `manage` / `approve` / `final` / `view` / `own` / `none`, `:team` for direct reports, `+` to combine); `LIMITS` holds the roles each role may give, audit areas and workspace per role. Check with `can(who, action, feature)` / `canFor(..., employeeId)` / `visible(...)`; in components `useCan` / `useWho` (`lib/useCan.ts`). Never test a role name in a component. The mock API enforces the same table: `deny(feature, action, employeeId?)` from `lib/session.ts` (the signed-in account, like a server session) at the top of every endpoint, returning a 403 `ForbiddenError`; lists are filtered by scope. Pages map to features in `featureForPath` (`administration/access.ts`); `usePageAllowed` + `filterNav` hide sidebar items, a blocked address shows `NoAccess`, and each Start-menu item states the `action` (and `feature`, when its page belongs to another) it needs, so links like "Approve overtime" only show to roles that can do it. Claims: employee → approver (`pending` → `endorsed`) → accounting final (`approved`); each step stores who, when and why. Accounting then releases the money straight to the employee (`releaseClaims`: cash, bank transfer, e-wallet or check); reimbursements never go through a payroll run. Payroll: accounting prepares and gives the final approval (`approveRun` needs `final`). One account per employee record (`createAccount`). The matrix is shown to people on Roles & access (`RolesPage`, only under Admin settings › Roles & permissions; `/admin/administration/roles` redirects there): pick a role to see its access in plain words, grouped from most to least (Can do everything · Can add and change · Gives the final approval · Can approve or decline · Can only look · Only their own, each item tagged "Their team only" when scoped, and a folded "No access" list), or "Compare all roles" for the full matrix with one icon per cell and a legend. Built-in role changes ship with a `ROLES_VERSION` bump in `lib/admin/store.ts` (old roles map once: Super Admin → super_admin, Admin/HR → hr, Partner → approver, others → employee, logged in the audit trail). Overtime and undertime (employee Requests › Overtime / Undertime) go straight to the approver; roles that can't approve them (HR, Accounting) only see them once approved (`listRequests` filters, the report page shows only the Approved tab). Payroll: accounting prepares and gives the final approval (`approveRun` needs `final`). Pay rules follow MSMA's payroll workbook (`lib/pay/engine.ts`, worked examples in `npm run check:payroll`): cut-offs close on two editable paydays, 10th and 25th by default (`lib/pay/settings.ts`: `cutoffOf`, `cutoffsOf`, `recentCutoffs`; Payroll › Pay details › Paydays); daily = monthly × 12 ÷ 261, hourly = daily ÷ 8; per-employee pay settings (5-day or 6-day work week, transport allowance prorated by days attended and not taxed, OT meal per overtime day, de minimis and other non-taxable pay taken off taxable pay); absences cost the day's hours (8, or 7 / 5 on a 6-day week), 30+ minutes late or every 3rd late in a week = half day, undertime = a flat 4 hours; premiums and overtime from the workbook's day-type table (`DAY_RATES`); contributions are not taken off before tax (sheet D). The Six-day week shift ends Saturdays early (`saturdayEnd`). Payouts split bank lists per bank and the journal by department. Runs that overlap another run's dates are refused.
- **Subscription & seat limits** (`lib/subscription/`, `features/subscription/shared.tsx`): one seat = one non-Separated employee; admin accounts = active hr/approver/accounting logins; both computed, never stored. Plans hold both limits and `gracePercent` (rounded down to whole seats); a client has renewal date, optional seat override and a temporary extension (+N seats until a date). Only adding is ever blocked: every create path calls `assertSeatsAvailable` (409 `SEAT_LIMIT_REACHED`), account create/promote/re-enable calls `assertAdminAccountAvailable`; never add seat checks to payroll, attendance, leave or reports. Call `checkSeatThresholds()` after anything that changes the head count; alerts go out once per crossing through `notifyRoles` (`lib/notifications.ts`, shown in the bell): Super Admin and HR get "Employee seats are almost full" at 80%, "Only N seats left" at 90% and "All employee seats are used" at 100% (tracked by `lastSeatAlert`); System Admins get 90% and 100%. Features: `subscription` (view: super_admin, hr), `subscriptionUpgrade` (super_admin), `clients` (system_admin: Administration › Clients & Subscriptions). UI: `SeatChip` in the top bar from 80% (a 36px pill "⚠ 17 / 20 seats", `.seat-chip` on the field fill, warning icon orange while seats run low and red (`data-full`) once every plan seat is used, the panel matching; the panel shows the seats left in the caution orange (heading, icon and bar the same colour); Request upgrade in its panel is `.btn-strong` (dark slate `--surface-strong`); opens a panel with View plan / Request more seats; no banner over the pages), `SeatNotice` (from 80%, on the Home dashboard only, since on other pages a corner card can cover a form's buttons: a corner card in `AdminLayout` at bottom-right above the assistant button: "17 of 20 seats used · 3 left…", bar, one action (Request more seats for super_admin, View plan for hr), close hides it for this sign-in only — it shows again after the next login (`markSignInTime`/`signInTime` in `lib/session.ts`) or sooner if fewer seats are left), `SeatIndicator` on People, Settings › Subscription (Admin settings for super_admin, HR settings read-only for hr), `SeatLimitDialog` when an add is refused (Request upgrade for super_admin, "Contact your administrator." for hr). Seeded demo: Starter, 20 seats, 8 admin accounts, 5% grace. `npm run check:subscription` runs the rules as each demo account.
- **Notifications** (`lib/notifications.ts` + `lib/requestNotices.ts`): every request, decision and HR change puts a bell notification in front of the person who has to act or is affected, like any app's inbox. Recipients follow the assigned roles: filing leave, overtime/undertime or a time adjustment → `tellApprover`, which reads the approval workflow (Administration › Workflows, `approversFor` in `lib/admin/approvers.ts`): every step that applies, i.e. the supervisor (Super Admins when they have no active Approver login), the department head (HR when there's none) or the step's role, with long-leave steps counted by days; claims (no workflow) go to the supervisor. Next steps → `tellAssigned(action, feature)`, the roles the access matrix assigns company-wide (`rolesThatCan`; Super Admin only when no other role has it): endorsed claims → final approvers (Accounting), 201 uploads → whoever checks documents (HR), certificate requests → self-service managers (HR), separations → payroll final (Accounting). Deciding → `tellEmployees` (approved / rejected, with the note); HR changes to someone's records (credits, schedule, shift, loans, payslips, documents, manager, role) → that person; company-wide news (remote work days, published policies) → `EVERYONE`. Each topic's `LINKS` sends every role to its own page. `notify` records who acted and never tells them about their own action. Add a call in the mock API whenever a new request type or decision is added; `npm run check:notifications` runs the flows as each demo account.

- **Pinned page top** (`useStickyPageTop` in `RolePage`, every workspace): the page heading (`ContentHead`, marked `data-page-head`) and the rows right under it that are tabs, short control rows (`Toolbar` is marked `data-page-top`; any row up to 96px with a search, select, tablist or button group counts) or a one-line caption stay pinned while the content scrolls. Each row pins exactly where it rests (its gap below the top bar is kept, up to 64px), so nothing shifts when scrolling starts; each covers the gap below it with `--bg`, and the first one (`data-page-top-first`) also covers the space up to the top bar. A page table's column headers pin under them at their resting inset in the card (`table[data-sticky-head]`, `--sticky-head-inset`), but only when the table fits its box (a table that scrolls sideways keeps its normal header). Don't use pill `FilterChip`s for status views.
- **Scrollbars:** panels and lists get slim rounded thumbs with no arrow buttons (`--scrollbar-thumb` / `--scrollbar-thumb-hover`, light and dark), set globally in `@layer base`; the page itself draws none.
- **Tables:** global rules — tinted uppercase header, `--line` dividers, `--nav-hover-bg` row hover; wrap wide tables in `overflow-x-auto`.
- **Charts:** bars/lines `--chart-bar`, highlight via an SVG gradient using `--chart-highlight-top/bottom` and `--chart-highlight-glow`, axes `--text-muted`, grid `--line`, glass tooltips. Categorical series (e.g. payroll segments) use `--color-cat-1..4`.

### Spacing
- Everything on a 4px scale (4, 8, 12, 16, 20…); no 6px/10px one-offs. Check spacing on every visual change, not only colors.
- Sidebar rhythm: 2px between rows, 16px before each group heading or the first module row after a group, 2px between stacked module rows, 4px under a heading.
- Alignment: page labels start 42px in from the list edge (12px padding + 20px icon + 10px gap). Sub-page lists put their guide line under the icon centre (22px) and their text on that same 42px line; the active icon tile (32px) uses negative margins so labels don't shift.
- Controls in one row share a height (top bar: 36px).

### Accessibility
- Text ≥ 4.5:1 in both modes (check muted text on the translucent cards, not just on the plain background).
- Every interactive element keeps a visible `:focus-visible` ring (global fallback in `@layer base`); icon-only buttons need `aria-label`.
- `prefers-reduced-motion` disables transitions, animations and transforms globally.
- Without `backdrop-filter` support, glass tokens become 94% opaque.
